# Checklist de frontend

- [ ] Usa componentes y tokens existentes; no duplica patrones por módulo.
- [ ] Funciona desde 320 px y en WebView Android, teclado y touch.
- [ ] Tiene estado de carga, vacío, vacío filtrado, error, permiso y sin conexión donde aplican.
- [ ] Formularios tienen labels, validación de campo, submit pendiente y resultado claro.
- [ ] Las mutaciones muestran pendiente, éxito o error; las acciones irreversibles tienen confirmación adecuada.
- [ ] Texto largo, imágenes ausentes, listas extensas y solicitudes lentas no rompen el layout.
- [ ] Respeta contraste, foco, iconos con etiqueta accesible y jerarquía para uso exterior.
- [ ] No expone IDs, proveedor, framework, endpoint, path de archivo o moderación interna al ciclista.
- [ ] Usa Wayfinder para conexiones frontend-backend cuando corresponde.
- [ ] Se ejecutaron `types:check`, `lint:check`, `format:check` y build si aplica.
