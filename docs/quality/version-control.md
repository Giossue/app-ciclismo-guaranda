# Control de versiones

- Revisar el diff completo antes de preparar archivos.
- Un commit = una unidad coherente (migración + código + test + docs que le corresponden).
- No mezclar refactor sin relación, cambios de formato ajenos, secretos, `.env`, outputs, dependencias o cambios de otro autor.
- Mensaje: `type(scope): verbo imperativo`, menos de 72 caracteres. Cuerpo opcional, máximo tres líneas útiles.
- Ejecutar validación proporcional antes de confirmar.
- Push, PR, cambios de rama o reescritura de historia requieren solicitud explícita del usuario.
